# Time extractor в Docker

Первый этап: интерфейс и работа с файлами. HTTP-загрузка из 1С через /api/dialogs и /api/tickets отключена: сервер отвечает 503 с пояснением и не делает исходящих запросов. Старый server.js сохранён; контейнер запускает отдельный docker-server.js.

## Запуск и обновление

Из чистой рабочей копии ветки main:

```bash
cd /opt/time-extractor
bash deploy.sh
```

Скрипт проверяет ветку, origin и отсутствие локальных изменений, выполняет git pull --ff-only origin main, docker compose up -d --build, ждёт healthcheck и проверяет файлы интерфейса. Если запуск неуспешен, он сообщает ошибку; автоматического отката нет. Расписание обновлений не подключено.

Порт хоста по умолчанию 8080, внутри контейнера 3000. Для настройки адреса и порта можно скопировать .env.example в .env; пароли для запуска не нужны.

Открыть интерфейс через доступный адрес сервера, например http://10.99.0.1:8080/. Проверить /health. После обновления проверить страницу и расчёт на своём тестовом файле. Успешный healthcheck не доказывает доступность порта с компьютера пользователя.

Существующий Nginx и его настройки не изменяются, нативный сервис не удаляется. Контейнер перезапускается с unless-stopped.

## Проверка

```bash
docker compose ps
docker compose logs --tail=50 app
curl --fail --max-time 10 http://127.0.0.1:8080/health
```

Статический сервер отдаёт только явный список файлов интерфейса. .git, .env, server.js и прочие служебные файлы через него недоступны. Образ не содержит Git-историю, конфигурацию сервера и секреты.

PDF-экспорт использует библиотеки из внешних CDN в браузере: для него компьютеру пользователя может понадобиться интернет. Подключение разрешённых сервисов 1С и проверка /api/tickets — отдельный следующий этап.
